# Шаблон scroll-landing

Еталонна реалізація: `evostone-es/` (лендинг evostone.es, ES/EN/RU). Клієнт її затвердив («охеренно»), тож для нового лендингу **копіюй цю папку**, а не пиши з нуля. Спершу прочитай `evostone-es/README.md` і `docs/ES_LANDING_estructura_v1.md`.

## Порядок роботи з клієнтом
1. Спершу структура, коду поки немає. Документ `docs/<NAME>_estructura_v1.md` має містити позиціонування, аудиторії, розділи зверху вниз з чернетками заголовків, правило «не перевантажити», план анімації, SEO-каркас і список питань до клієнта.
2. Після відповідей клієнта верстка. Фото поки заглушки, ціни «від» (орієнтовні позначаємо як ⚠).
3. Перегляд публікуємо як Artifact (див. «Прев'ю» нижче).

## Архітектура (без фреймворків)
```
<site>/
  build.mjs              node build.mjs → index.html, <lang>/index.html, sitemap.xml, robots.txt
  src/data.mjs           SITE (бренд, контакти), LANGS, PRICES, PRODUCTS, MATERIALS, SERIES…
  src/content/<lang>.mjs усі тексти мовою; price(p) і faq.a(P) — функції
  src/template.mjs       render(t, lang): один шаблон на всі мови
  assets/css/style.css   токени бренду + усі розділи
  assets/js/main.js      вся взаємодія й анімація
  assets/js/config.js    formEndpoint, GA4/Pixel (без перезбирання)
  assets/vendor/         gsap, ScrollTrigger, lenis (локально; lenis узяти через `npm pack lenis`)
```
Згенеровані HTML руками не правимо. Нова мова = новий `src/content/<code>.mjs` + рядок у `LANGS`.

## Розділи (кожен розділ = одна думка)
00 прелоадер (лише 1-й візит у сесії) → 01 Hero на весь екран (H1 у 2 рядки + рядок-«хвіст» моношрифтом, CTA + WhatsApp, рядок довіри) → 02 Маніфест (слова проявляються + 3 лічильники) → 03 Продукти (горизонтальна pin-галерея, картка: фото, №, назва, 1 речення, теги, ціна «від», «Ver más» → drawer) → 04 Колекція (великі назви-таби + фото з clip-переходом) → 05 Матеріали (темний блок, marquee контурним шрифтом, 4 картки) → 06 Процес (sticky фото + кроки) → 07 Проєкти (bento, clip-reveal) → 08 Для професіоналів (фірмовий колір, рядки з hover) → 09 FAQ (details + FAQPage schema) → 10 Контакт (величезний заголовок, форма з чипами, WhatsApp) → футер з гігантським словом бренду.

Деталі продуктів не розширюють сторінку: вони лежать у `drawer` прямо в HTML (для індексації), а показуються по кліку.

## Анімація: ключові прийоми
- **Тема фону:** секції мають `data-bg="paper|sand|dark|brand"`. `main.js` через GSAP анімує CSS-змінні `--bg --fg --mute --line --accent` на `<html>`. Усі кольори компонентів беруться з цих змінних. Без JS кожна секція має власний фон (`html:not(.js) [data-bg]`).
- **Заголовки:** рядки задаються масивом у content, `lines()` обгортає кожен у `.ln > span`, анімація `yPercent 110 → 0`.
- **Плавний скрол:** Lenis підключено до `gsap.ticker`. Якірні посилання йдуть через `lenis.scrollTo`, а коли відкрито drawer або меню, скрол зупиняється.
- **Горизонтальний pin:** працює через `gsap.matchMedia` лише при ≥900px і без reduced-motion. На телефоні замість нього нативний scroll-snap.
- **Курсор і магнітні кнопки:** тільки для `(hover:hover) and (pointer:fine)`.
- **`prefers-reduced-motion`** вимикає прелоадер, pin і scrub-анімації.

## Граблі, на які вже наступили
- **ScrollTrigger для теми створюй ПІСЛЯ pin-секцій**, інакше кольори перемикаються не там (pin додає висоту).
- **Не використовуй `data-track` для чогось, крім аналітики.** Галерея має `data-htrack`, і змінна в JS теж не `track`, бо `track()` — це функція аналітики.
- **`.ln` потребує `padding-top`**, інакше `overflow:hidden` зрізає акценти над великими літерами (Á, Ó, Й).
- **`.menu > nav`, а не `nav:first-child`**, бо інакше під стилі потрапляє мовний перемикач.
- **Заголовки в drawer потребують відступу справа** під кнопку закриття.
- **Не більше 2 рядків у H2 при 1440px.** У split-шапках заголовок займає всю ширину, а `lead` стоїть під ним праворуч.

## Посадкові сторінки під запити
Еталон: `evostone-es/src/landings/es.mjs` + `src/landing-template.mjs` (20 сторінок, ES). Одна сторінка закриває один продуктовий намір, щоб сторінки не конкурували між собою. Структура сторінки: хлібні крихти + H1 з ключем + ціна «від» + фото → вступ на 70–100 слів → 4 переваги → таблиця технічних даних → галерея з 3 фото → 4 кроки процесу → FAQ на 3 питання (schema) → 3 пов'язані сторінки → форма з прихованими `product` і `landing`. Головну при цьому **не чіпаємо**: окремі `landing.css` і `landing.js`. Після збірки перевір `git diff` по `index.html`, `en/`, `ru/`: там має бути порожньо. Частотність запитів без Keyword Planner — лише оцінка, так і пишемо клієнту.

## Заглушки фото
`<img data-ph="…">` з неіснуючим файлом замінюється плашкою з іменем файлу (`data-tone` дає фактуру матеріалу). Щоб прибрати заглушку, клієнт просто кладе файл з цим іменем у `assets/img/`.

## Перевірка перед комітом
Підніми `python3 -m http.server` і прожени Playwright: `$(npm root -g)/playwright`, Chromium уже встановлений. Зроби скріншоти 1440×900 і 390×844 кроками по скролу, перевір `pageerror`, drawer, чипи форми, меню.
